About

Poet Music

Version 1.4.0 · offline-first, pastel-themed music player.

Your library holds 418 tracks across 2 folders.

The UI is an htmx single-page app served by an embedded Ktor server running inside the app process and rendered in a native WebView. Playback is handled natively by Media3 / ExoPlayer through a foreground MediaSessionService.

Tech stack

  • Language — Kotlin
  • UI — htmx single-page app in a native WebView
  • Server — embedded Ktor (CIO) bound to 127.0.0.1:8080
  • Playback — Media3 / ExoPlayer in a foreground MediaSessionService
  • Storage — SQLite (tracks, folders, playlists, settings)

Security & privacy

  • Local-only server — not reachable from other devices.
  • No network calls — no analytics, no user data transmitted.

Decisions this mockup commits to

Now Playing never scrolls (§1)

  • The cover art is the flexible element — flex:1 1 auto; min-height:0; aspect-ratio:1 — so it shrinks first and the chip row is never pushed off-screen. It replaces the fixed min(78vw,320px).
  • The chip row is a single non-wrapping line with overflow-x:auto as the last-resort fallback, so speed / sleep / lyrics / favourite / queue all stay reachable without the page growing.
  • Toggling lyrics shrinks the art rather than extending the page; the deck is the only scroller. Try Lyrics on in every mode — the page never gains a scrollbar.
  • Controls step down by tier (main 76 → 56px, side 52 → 42px, dot 44 → 34px) instead of wrapping.
  • The mini player is hidden whenever Now Playing is a full route — portrait, landscape and tablet. It duplicates the transport sitting directly above it and costs ~68px of the height the art needs. Implemented by zeroing --tray-h, so every rule keyed off it reclaims the space. The PC tiers override it: there Now Playing is a pane and the bar is the player.

Tablet

  • Now Playing puts the cover art on top with every control centred beneath it. The landscape two-column split is the wrong instinct on a portrait-shaped 834 × 1112 panel: it shrinks the art and pushes the controls into a narrow side gutter.
  • The space freed by hiding the mini player becomes an inline tag editor for the playing track — tablet only. Toggle Lyrics on and the lyrics deck takes that slot instead, so the two never compete.
  • Elsewhere the tablet keeps the 210px labelled rail, 2-column lists and centred dialogs.

Landscape mobile

  • The header is the wrong shape when height is the scarce axis — it becomes a 56px icon rail, which also gives the library tabs a permanent home.
  • Bottom sheets become side sheets. A 90%-height bottom sheet on a 360px-tall screen is unusable; the queue, sort drawer, sleep timer and tag editor all dock to the right edge instead.
  • Now Playing is art | controls, and lyrics slide in as a third column rather than replacing anything.
  • Turn on Show cutout: the rail and the overlay bodies carry the --safe-l gutter, so nothing lands under the notch. This only works once the Activity opts into windowLayoutInDisplayCutoutMode (§3.1) — the black band in the reference screenshot is the system letterboxing the window, not a CSS bug.

PC — Groove-style single window

  • Now Playing stops being a route. It is a permanent right-hand pane, so basic control never costs a navigation, and the transport bar spans the full window — rail included — with an inline seek.
  • The queue docks into that same column instead of covering the window — on PC wide both are visible at once (three columns: rail · library · NP + queue).
  • Journal, About and the Tag editor become centred card modals over the shell, replacing the full-screen takeovers. The Journal body goes 2-column at PC compact and 3-column at PC wide.
  • Prose is capped at 68ch so About and the Journal narrative stay readable at 1920px.
  • Hover and :focus-visible states appear only at the PC tiers — the touch build has :active only.

The 480px cap

  • Replaced by one --shell-w custom property. Today the literal 480px is repeated across #app, #tray, #cab, .drawer, .sheet, .queue-panel and .editor-sheet; each tier here sets the property once and every surface follows.

Review checklist (§2.5)

  • Nothing dropped — every portrait element has a home in every mode: library tabs → rail items; header nav → rail; bottom sheets → side sheets → dialogs; Now Playing transport → transport bar on PC.
  • Touch targets — ≥44px in portrait, ≥34px in landscape mobile (the compact tier from §1.2), denser only at the PC tiers where the pointer is the input.
  • Both themes — flip Dark in each mode. Dark drops every backdrop blur, matching the WebView compositing workaround already in poet.css.
  • Breakpoints written down — the table above is the set §3.3 implements. No re-deriving them later.

Known gaps (deliberate)

  • Album/artist/genre detail screens reuse the songs-list layout and are not mocked separately.
  • The multi-select action bar (#cab), onboarding tip and toast are not mocked; they follow --shell-w and need no independent layout decision.
  • Motion is out of scope — the sheet-up keyframes bake in the -50% centring translate and will need revisiting when --shell-w lands (§3.2).
